# 数据集版本

每个任务使用一份独立的数据副本。Studio 中的裁剪、片段删除、任务文本和标注先保存到任务副本；审核通过后，再复制完整数据包并发布新版本。原数据集与已经发布的版本都不覆盖。

## 使用

1. 新建任务，选择数据集、起始版本、标注负责人和审核负责人。起始版本可以是原始数据集，也可以是某个已有的完整发布版本。
2. 进入工作区。平台先复制任务副本，再打开 Studio。
3. 编辑完成后点击工作区左下角的「保存修改」。有未保存修改时，点击「返回数据平台」也会先保存。保存期间请等待完成；失败或取消不会替换上一次成功保存的数据。
4. 返回任务页，完成人工标注。指定审核负责人查看视频并确认质检；打回后回到标注阶段。
5. 质检通过后自动打包、发布。在版本管理中查看存储路径并下载完整数据包。

每次发布生成 V1.0、V2.0 等新编号。V1.0 是第一次发布的结果，并不代表未标注的原始数据；原始数据集单独保留。

## 包里包含什么

- `data/`：修改后的 Parquet，片段和帧编号重新对应，时间从零开始。
- `videos/`：与数据行对应的视频；裁剪保存时实际截取视频内容。
- `meta/`：片段、任务、帧数、统计量等元数据。
- `segments/`：LabelVLA 文本、结构化标注、目标框、轨迹和 SAM 轮廓。
- `labelvla_revision.json`：这次修改的来源、片段映射、裁剪范围及保存人。
- 原数据集的其他附加文件也复制保留。根目录下已有的分片备份目录会占用额外空间。

裁剪会同步调整标注范围和轮廓帧号。删除片段后，剩余片段重新连续编号；导出任务副本时保留全部未删除片段，不会因为侧栏的临时多选而丢失其他片段。

## 存放位置

容器中的 `/data` 对应服务器的 `/home/robam/labelvla-docker/data`。

```text
/data/<原数据集>/                              原始数据集
/data/.platform/workspaces/task_<任务ID>/       任务初始副本
/data/.platform/drafts/<保存ID>/dataset/        每次成功保存的编辑结果
/data/.platform/releases/<数据集标识>/
  V1.0/
    snapshot/<数据集名称>_V1.0/                 第一版完整目录
    snapshot/manifest.json                     文件清单与来源信息
    dataset.tar.gz                            第一版完整压缩包
  V2.0/
    snapshot/<数据集名称>_V2.0/                 第二版完整目录
    snapshot/manifest.json
    dataset.tar.gz
```

每个版本都是实际文件副本，没有使用指向原数据的硬链接。平台拒绝修改发布目录；新一轮修改需要新建任务，选择对应的起始版本。备份时需要一起备份 `/data`，其中 `.platform/platform.db` 保存任务与版本记录。

升级前已经发生的修改不会被逆向恢复为原始数据；原始性只能由导入时的数据和已有备份确认。

## 视频依赖

内网 HTTP 不具备浏览器的全部视频解码能力，因此服务器负责视频裁剪和图像统计。安装方式见 [部署文档](deployment.md)。目前服务器保存支持视频特征；嵌入式图像和深度特征会给出不支持提示，不会用旧统计量冒充新结果。
