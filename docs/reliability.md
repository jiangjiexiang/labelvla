# 任务执行、数据隐藏与数据库升级

## 任务恢复

任务调度保存在平台数据库的 `task_jobs` 中，包含等待/执行状态、执行代次、重试次数及心跳。平台使用单个后台工作线程，当前部署保持一个服务实例。

重启时，只将原来处于 pending/running 的任务重新排队，保留已完成节点，重新执行未完成的自动节点。等待人工的任务继续等待；业务检查失败的任务仍需人工修正或重试，不会无限自动重试。视频上传或 Studio 保存中断仍需重新保存，已有成功保存的数据不被替换。

版本发布会检查已有发布记录，恢复后不会覆盖已发布目录。中断的临时文件保留在平台运行目录，不会作为成功结果使用。

## 取消

取消会设置停止信号，更新任务与持久队列状态，并取消未完成的保存记录。文件复制、校验、打包、质检循环会检查取消信号；FFmpeg 和注册的外部程序使用独立子进程组，由平台终止该任务启动的进程。原始数据、已有成功保存及已发布版本不删除。

停止响应取决于当前操作到达检查点的速度；正在执行的底层单次解码调用不能承诺毫秒级停止。新的执行代次不会被旧执行线程的结果覆盖。

## 数据管理的“删除”

原始 data 挂载继续只读。“删除”仅在平台数据库标记隐藏，从数据列表和新建任务选择列表移除，不移动原始文件。回收站恢复时清除隐藏标记。已创建任务仍能访问自己的副本。

机器人标签也保存到数据库。已有数据集 `_platform/robot.json` 中的标签作为兼容读取来源，不再写回原始数据集。

历史版本放在 data/.trash 的物理回收站目录仍可查看；此类旧条目需要管理员在宿主机恢复文件后重新扫描，平台不会绕过只读挂载移动它们。

## 数据库迁移与恢复

统一入口：`backend/bridge_ext/migrations.py`。版本记录：`schema_migrations`。

1. `adopt_existing_schema`：接管已有表结构、任务编号及历史兼容迁移。
2. `persistent_tasks_and_dataset_preferences`：增加持久任务队列和数据集隐藏/标签记录。

未来结构变更应添加新的迁移版本，不修改已应用版本。原模块的初始化入口统一转交迁移管理器，历史初始化逻辑仅用于版本 1 接管。

升级前使用 SQLite backup API 生成一致快照，保存在 `data/.platform/migration_backups/`。升级失败时恢复升级前数据库并停止启动，错误详情记录在 `data/.platform/migration_error.json`。应用持有数据库实例锁，避免同一数据库被两个服务进程同时启动。

手动恢复须先停止服务，并准备与备份匹配的代码版本：

```bash
docker compose stop app
docker compose run --rm --no-deps --entrypoint python app \
  -m bridge_ext.migrations restore /data/.platform/migration_backups/具体备份.db
```

恢复工具会拒绝在原服务仍运行时写入数据库，并再次备份恢复前的数据。确认代码版本后再启动；不匹配的新版代码会再次尝试升级。数据库备份不包含视频及 output 文件，完整备份仍须包含 data 和 output。

本次未执行任务中断、取消或删除/恢复的功能测试；由使用者进行验证。
